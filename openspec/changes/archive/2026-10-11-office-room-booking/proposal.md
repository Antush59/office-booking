# Предложение

## Зачем

Нужно учебное REST-приложение для бронирования переговорных комнат в офисе. Сервис должен давать понятное доменное ядро: список комнат, создание и отмена броней, поиск свободных слотов и свободных комнат. Изначально требовалось не сохранять данные между сессиями, но в ходе обсуждения это ограничение снято — данные теперь хранятся в БД и переживают перезапуск приложения.

## Что меняется

- Новый синхронный REST-сервис на Spring Boot 2.7 (Java 17, Maven) без UI, без авторизации и без ролевой модели.
- Доменная модель:
  - переговорная комната — название/номер и вместимость;
  - бронь — комната, имя пользователя, интервал времени (start/end) и статус (ACTIVE/CANCELLED).
- API для:
  - просмотра всех комнат с характеристиками;
  - просмотра свободных 15-минутных слотов конкретной комнаты на дату;
  - просмотра всех свободных комнат на заданный интервал даты;
  - создания брони с проверкой пересечений — при конфликте возвращается `409` с именем пользователя и интервалом конфликтующей брони;
  - отмены брони (soft-delete, перевод в статус CANCELLED).
- Хранение данных в PostgreSQL (Docker), схема управляется Liquibase.
- Тесты на TestNG, логирование LogBack.

## Возможности

### Новые возможности

- `room-booking`: инвентарь переговорных комнат и их бронирование — просмотр комнат и их характеристик, поиск свободных слотов и свободных комнат, создание и отмена броней с учётом занятости.

### Изменённые возможности

_Нет — существующих спецификаций в проекте нет._

## Влияние

- Новый код: Spring Boot-приложение (Java 17, Maven), JPA-сущности и репозитории, REST-контроллеры, сервисный слой, валидация интервалов и занятости.
- БД: PostgreSQL в Docker; схема через Liquibase — таблицы `rooms` и `bookings`.
- Тесты: TestNG (юнит-тесты сервисного слоя и интеграционные сценарии поверх БД).
- Логирование: LogBack.
